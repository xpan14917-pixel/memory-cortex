## 1. 面板功能与实现

### 1.1 能看到什么

| 区域 | 内容 | 实现 |
|---|---|---|
| 中央 3D 场景 | 14 个脑区、记忆之湖、检索光束、人格内核 | WebGL2 点精灵 + 光束四边形 |
| 皮层导航（左上） | 俯视小地图、雷达扫描、相机视锥、点选飞入 | Canvas 2D，坐标由 3D 位置投影 |
| 记忆构成（左下） | 事实/经历/喜好/约定 堆叠条 + 归档数 + 平均 R | DOM |
| 人格内核（右上） | 亲密度环、PAD、能量、五维雷达 | SVG + DOM |
| 认知流（右下） | 滚动日志 | DOM（**示例文案，非实时**） |
| 时间轴（底部） | 48h 活动条、记忆写入点、可拖动 | DOM + Canvas |
| 控制条 | 视角/显示/质量/检索/时间/导出/全屏 | DOM |

### 1.2 视觉实现要点

- **节点字形**：圆环 / 菱形 / 六边形 / 十字星 / 光晕，全部在 fragment 里用 SDF 画，缩放不糊
  （`js/gl.js` 的 `FS_POINT`，按 `aKind` 分支）
- **泛光**：亮部提取（阈值 0.72）→ 两段高斯 → 叠加 → ACES 色调映射 → 冷调 + 颗粒 + 暗角 + 色散
  （`gl.js` 的 `post()`；全屏后处理必须 `disable(BLEND)`，否则会跨帧累积成白屏）
- **记忆之湖**：长期记忆库是一片倾斜的点阵平面 + 金色体积光 + 上浮粒子
- **遗忘度上色**（2026-10-31 新增）：每条记忆节点 `size`、`glow` 跟保持度 R 走；
  `archived=1` 变成灰暗环。见 `js/data.js` 里 memory lake 那段
- **相机**：轨道相机 `yaw/pitch/dist/target`，平滑插值；自动巡航 0.03 rad/s

### 1.3 面板的数据从哪来

```
bot.db ──(只读)──> tools/build_data.py ──> js/data.real.js ──> 面板
```

`build_data.py` 会：
1. 只读打开 `bot.db`（`mode=ro`，不会写坏）
2. `import bot.forgetting` 算每条记忆的保持度 `retention`
3. `import bot.brainmap` 给每条记忆标 `region`
4. 输出 `persona / state / memories / messages / profile / counts`

单文件版由 `panel/build_single.py` 把 CSS 和 7 个 JS 内联成一个 html。

**刷新面板数据的两条命令**：

```bat
cd C:\path\to\qq-soul
python panel\tools\build_data.py
python panel\build_single.py
```

## 2. 记忆是怎么存、怎么取的

### 2.1 写入（每轮对话后自动）

```
用户发消息 → engine.handle
   → 回复发出去以后 → growth.reflect_async(用户这句, 她的回复)
        → LLM 抽 JSON：memories[] / profile{} / intimacy_delta / mood_delta
        → store.add_memory(kind, content, keywords, weight)
             ├ 去重：Jaccard ≥ 0.8 则合并（取更长的那句，权重 +0.2）
             ├ stability = forgetting.stability(kind, weight, hits)
             └ region    = brainmap.classify(kind, content, keywords)
        → store.upsert_profile(...)
        → growth.maybe_decay()  每天只跑一次
```

### 2.2 读取（每轮对话前）

```
engine._reply
   → brainmap.query_regions(用户这句)          命中哪些区
   → store.search_memories(text, limit=6, budget_tokens=320, regions=…)
        1. 关键词/字面命中 → 相关度
        2. score = 相关度 × R^0.9 × weight
        3. 分区命中 +0.6 分（只加分，不淘汰）
        4. 按 score 排序，前 3 条全文、之后截断，总预算 320 tok
        5. 选中的记忆做复习：hits+1、last_used=now、S×1.25
   → persona.build_chat_messages(...)
   → LLM
```

同一条链路还服务：主动消息（3 条）、内心活动（4 条）。

### 2.3 遗忘曲线

```
S = S0(kind) × (1 + 0.5×hits) × weight^1.2        # 稳定度，单位天
R = exp(-Δt / S)                                   # 保持度，1=刚用过
score = 相关度 × R^0.9 × weight
```

| 类型 | S0 | 说明 |
|---|---|---|
| 约定 promise | 120 天 | 永不归档 |
| 日子 date | 400 天 | 永不归档 |
| 喜好 preference | 45 天 | |
| 事实 fact | 30 天 | |
| 经历 event | 10 天 | 最快淡出 |

归档规则：`R < 0.05` 且 `hits=0` 且库龄 > 90 天 → `archived=1`（**不删**，只是不进 prompt）。

### 2.4 表结构（memories）

| 字段 | 含义 |
|---|---|
| id / ts | 主键 / 写入时间 |
| kind | fact / event / preference / promise / date |
| content / keywords | 原文 / 关键词（空格分隔） |
| weight | 重要度 0.6–3.0 |
| hits / last_used | 被召回次数 / 上次召回时间 |
| **stability** | 稳定度 S（天） |
| **archived** | 是否已淡忘（1=归档） |
| **last_review** | 上次复习时间 |
| **region** | 分区：routine / limbic / persona / neural / memory |

迁移是幂等的：`Store._migrate()` 在启动时检查缺哪列补哪列，并回填 stability / region。

## 3. 接入实时对话（让面板跟着动）

现状：**面板是快照**，不会自己更新。下面三条路线，按成本排序。

### 路线 A：定时导出 + 自动刷新（0 行代码，最省事）

1. Windows 计划任务每 60 秒跑一次：
   ```bat
   cd /d C:\path\to\qq-soul && .runtime\python\python.exe panel\tools\build_data.py
   ```
   （用 `qq-soul\.runtime\python\python.exe` 亦可）
2. 在 `index.html` 的 `<head>` 里加一行，页面每 30 秒自己刷新：
   ```html
   <meta http-equiv="refresh" content="30">
   ```
3. 缺点：会整页重载（闪一下），画质参数/视角会回到默认。

适合"偶尔看一眼"，不适合挂着当第二屏。

### 路线 B：本机小服务（推荐，约 80 行）

用一个独立进程同时做两件事：**托管面板静态文件** + **提供 JSON 接口**。
因为同源，浏览器不会有任何跨域问题。

新建 `qq-soul/tools/panel_server.py`（骨架，未落地）：

```python
import json, sqlite3, pathlib, time
from http.server import ThreadingHTTPServer, SimpleHTTPRequestHandler

ROOT = pathlib.Path(r"C:\path\to\qq-soul\panel")
DB   = pathlib.Path(r"C:\path\to\qq-soul\data\bot.db")

def snapshot():
    con = sqlite3.connect(f"file:{DB.as_posix()}?mode=ro", uri=True)
    con.row_factory = sqlite3.Row
    q = lambda s: [dict(r) for r in con.execute(s)]
    return {
        "ts": time.time(),
        "state": {r["k"]: r["v"] for r in q("SELECT * FROM state")},
        "counts": q("SELECT COUNT(*) n FROM memories")[0],
        "memories": q("SELECT id,kind,content,weight,hits,stability,archived,region,last_used,ts"
                      " FROM memories ORDER BY ts DESC LIMIT 300"),
        "messages": q("SELECT ts,role,content FROM messages ORDER BY ts DESC LIMIT 60"),
        "profile": q("SELECT * FROM profile"),
    }

class H(SimpleHTTPRequestHandler):
    def __init__(self, *a, **kw):
        super().__init__(*a, directory=str(ROOT), **kw)

    def do_GET(self):
        if self.path.startswith("/api/state"):
            body = json.dumps(snapshot(), ensure_ascii=False).encode()
            self.send_response(200)
            self.send_header("Content-Type", "application/json; charset=utf-8")
            self.send_header("Cache-Control", "no-store")
            self.send_header("Content-Length", str(len(body)))
            self.end_headers()
            self.wfile.write(body)
            return
        super().do_GET()

    def log_message(self, *a):
        pass

ThreadingHTTPServer(("127.0.0.1", 8090), H).serve_forever()
```

面板侧（`js/main.js` 加约 40 行；`HUD.applyLive` / `Scene.rebuildMemories` 需要新增）：

```js
const LIVE = new URLSearchParams(location.search).has("live");
async function pull() {
  const s = await (await fetch("/api/state", { cache: "no-store" })).json();
  HUD.applyLive(s);           // 只更新数字/人格卡/构成条/认知流
  if (s.counts.n !== BRAIN.stats.memories) Scene.rebuildMemories(s.memories); // 记忆数变了才重建
}
if (LIVE) setInterval(pull, 3000);
```

打开方式改为：`http://127.0.0.1:8090/index.html?live=1`
（必须用 http 打开，不能用 file://，否则 fetch 会被拦）

把 `panel_server.py` 放进 `start_bot.bat` 一起启动，或单独开一个窗口常驻。

### 路线 C：事件推送（SSE，最实时）

在 B 的基础上，`panel_server` 每 1 秒查一次 `memories` 的 `MAX(id)`，变了就向所有 SSE 连接推一条。
面板用 `new EventSource("/api/stream")` 接收。比轮询省电，但要处理断线重连。

**建议**：先上 B，够用再考虑 C。

### 3.1 记忆"写入"也想从面板点？

现在面板是只读的。要支持手动加一条记忆，只需在 `panel_server` 加一个 POST：

```python
# POST /api/remember  {"kind":"fact","content":"..."}
from bot.store import Store           # 直接复用机器人那套逻辑（含去重/分区/稳定度）
Store(DB).add_memory(kind, content)
```

面板上弹个小输入框即可。注意：**同时开着 bot 时**，两个进程都写同一个 SQLite，WAL 模式支持并发写，但会短暂锁表（timeout 15s 已设）。

## 4. 换新窗口怎么"重新创建她"

这里有两种"新窗口"，别混在一起。

### 4.1 小小自己换窗口（重启 bot / 换模型）—— 她不会失忆

她的记忆在 `bot.db`，不在任何聊天窗口里。每轮 prompt 都是临时从库里拼出来的：

```
人格卡 + 13 条规则（静态）
+ 当前时间/状态 + 记忆分区 + 召回的 3~6 条记忆 + 档案前 10 条 + 最近 10 条对话
```

所以：

| 操作 | 她会失忆吗 | 怎么做 |
|---|---|---|
| 重启 bot | 不会 | `start_bot.bat` |
| 换 LLM（DeepSeek→Ollama/本地） | 不会 | `tools\set_llm.py --base … --model … --key … --test`，再重启 |
| 换电脑 | 会，除非带走 db | 拷 `data/bot.db`+`-wal`+`-shm`、`persona.json`、`config.json` |
| 删库 | 会 | 从 `data/bot.db.bak-*` 或 `backups/*/bot.db.snapshot` 恢复 |

**唯一真相是 `data/bot.db`**。只要它还在，她永远是同一个她。

### 4.2 你换一个 AI 编码窗口 —— 用交接包

新开一个对话，把下面这段整个粘进去（这是"重新创建她"的正确方式：不是重建数据，是重建**上下文**）：


## 6. 已知限制

1. 面板的「认知流」是**示例文案**，不是她的实时日志 —— 要看真相请 `Get-Content logs\bot.log`。
2. 面板是快照，需要手动或定时导出才会更新（见第 3 节）。
3. 分区是规则式关键词匹配，会误判；因此只加分、不淘汰。
4. 遗忘曲线要 2–4 周才看得出分流（现在 57 条全是新鲜的，最快淡忘的 R 也有 0.9）。
5. 主动消息/内心活动也吃记忆，但走的是同一套召回，预算各自独立。
