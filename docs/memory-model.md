# 记忆模型

## 一句话

每条记忆有一个**稳定度 S**（天）和一个**保持度 R**；被想起时 S 变大（曲线变平），
不被想起时 R 随 `exp(-Δt/S)` 衰减；R 太低且从没被用过，就归档（不删）。

## 公式

```
S = S0(kind) × (1 + 0.5 × hits) × weight^1.2      # 稳定度，天
R = exp(-Δt / S)                                   # Δt = 距上次被用（last_used 或 ts）的天数
score = 相关度 × R^γ × weight                      # γ 默认 0.9
```

- `hits`：被召回次数；每次召回 `hits+1`、`S *= 1.25`（间隔重复）
- `weight`：写入时的重要度（0.6–3.0），由反思模型给出
- `γ`：让 R 对排序的影响略微钝化，避免"刚写的永远第一"

## 初始稳定度

| kind | S0 | 归档 |
|---|---|---|
| promise 约定 | 120 天 | 永不 |
| date 日子 | 400 天 | 永不 |
| preference 喜好 | 45 天 | 90 天后可 |
| fact 事实 | 30 天 | 90 天后可 |
| event 经历 | 10 天 | 90 天后可 |

## 召回

1. 候选：`archived=0`，按 `weight DESC, ts DESC` 取 400 条
2. 相关度：关键词命中 ×2，字面子串 ×0.3（至少命中一个，否则不召回）
3. 分区加分：`query_regions(text)` 命中的区 +0.6（**只加分，不淘汰**）
4. 过滤：`R < min_retention(0.06)` 且非钉住类型 → 丢弃
5. 排序 + 预算：前 3 条全文，之后截断到 14 字，总预算 320 tok
6. 写回：选中项 `hits+1 / last_used=now / S×1.25`

## 归档

每天第一次反思后运行一次：

```
R < 0.05 且 hits == 0 且 库龄 > 90 天 且 kind ∉ {promise, date}  → archived=1
```

归档只是不进 prompt，数据仍在，可以 `#遗忘` 里看到，也可以手动改回 `archived=0`。

## 参数（`config.json` 的 `memory` 段）

| 键 | 默认 | 作用 |
|---|---|---|
| `top_k` | 6 | 单轮最多召回条数 |
| `budget_tokens` | 320 | 记忆块 token 上限 |
| `min_retention` | 0.06 | 低于此 R 且非钉住 → 不召回 |
| `gamma` | 0.9 | R 的指数 |
| `review_boost` | 0.25 | 每次复习 S 的增幅 |
| `archive_min_retention` | 0.05 | 归档的 R 阈值 |
| `archive_min_days` | 90 | 归档的最小库龄 |
| `profile_top_n` | 10 | 注入 prompt 的档案条数 |
| `brainmap_enabled` | true | 是否注入分区摘要 |
| `brainmap_budget_tokens` | 60 | 分区摘要的预算 |

## 为什么这样设计

- **不做硬过滤**：分区靠关键词猜，猜错时硬过滤会直接漏掉正确记忆；加分错了只是排序偏。
- **约定永不归档**：承诺是关系里最不能丢的东西，宁可占一点上下文。
- **归档不删除**：遗忘应该是"想不起来"，不是"没有过"，而且误判可恢复。
- **预算按 token 不按条数**：一条长记忆可能顶掉三条短记忆，按条数切不划算。

## 已知不足

- 关键词召回对**改写**不敏感（"我让你怎么叫我来着" ↛ "希望被称呼为阿明"）；
- 没有向量召回、没有冲突覆盖（改口后旧事实仍可能被召回）；
- token 是字符估算（中文 ≈1.6 字/token），不是精确 tokenizer。
